# test_proxy — 프로젝트 규칙 (프록시 테스트)

리디 응답 필드를 프록시로 조작해 웹/앱 지면을 검증하는 도구 프로젝트.
이 파일은 **이 디렉터리에서 작업할 때의 규칙·컨텍스트**만 얇게 담는다.

| 찾는 것 | 문서 |
|---|---|
| 실행 워크플로우 (트리거·패널·폴링·검증 절차) | `.claude/skills/proxy/SKILL.md` |
| 실측 사례·근거·기기 정보 등 상세 로그 | `MEMORY.md` |

---

## 🔒 최상위 규칙 — 스코프

- 프록시 관련 작업(코드·설정·규칙·문서·노트)은 **`test_proxy/` 안에서만** 생성·수정·반영한다.
- 루트(RIDI-QA-Auto)나 다른 프로젝트 파일, **공용 메모리(`~/.claude/.../memory/`)는 건드리지 않는다.**
- proxy 규칙·교훈은 `CLAUDE.md`·`SKILL.md`·`MEMORY.md`에 **자체 보관**(외부에 흩뿌리지 않음).

## 📁 구성

| 파일 | 역할 |
|---|---|
| `proxy-engine.js` | 웹 rule-engine 프록시 + 컨트롤패널(`/__qa`). Node 무의존. 포트 **3001**, 업스트림 `ridibooks.com` |
| `mitm_addon.py` | 모바일(AOS/iOS) mitmproxy 애드온. 같은 `rules.json` 공유. 포트 **8888** |
| `rules.json` | 조작 규칙(웹·모바일 공유). 패널의 규칙 추가/삭제가 갱신 |
| `server.js` + `overrides.json` | 기존 dev.ridi.io 프록시(포트 3000). **이 스킬과 무관 — 건드리지 않음** |
| `.claude/skills/proxy/SKILL.md` | 프록시 테스트 실행 워크플로우(스킬) |
| `MEMORY.md` | 실측 사례·근거·기기 정보 로그 |

## 📌 운영 원칙 (실측으로 굳은 규칙)

1. **패널 기반·무질문·자동폴링.**
   `proxy` 입력 → 엔진 기동 + `open …/__qa` + `/__proxy/signal` 백그라운드 폴링 자동 시작. "누르셨나요?"라고 되묻지 않는다. 사용자는 이후 **패널만** 보고, 결과 소통도 패널(`/__proxy/result`)로. 한 테스트가 끝나면 폴링 재기동 → 시작/종료를 세션 내내 자동 감지.

2. **환경은 확인, 가정 금지.**
   전 환경이 `ridibooks.com` 공유(URL/API 경로 동일) → 실제 환경은 응답 헤더 `x-ridi-environment`(stage/canary=해당, 없음=prod)로 확정. 패널 `targetEnv`는 라벨일 뿐이므로 **불일치 시 실제값을 게시**. 띠지는 보조.
   - **모바일 표준 워크플로우**: 사용자가 **mac VPN으로 환경을 사전 세팅** + **패널 라벨로 선언**한다. 나는 매번 VPN을 요구하지 않고 라벨을 접수해 진행하되, **실 트래픽 헤더가 라벨과 다르면 그때만 알린다**. 헤더주입은 **OFF**(VPN과 이중·앱 인증 오염 위험). 감지는 `mitm_addon.py`의 `[ENV]` 로깅(실제 폰 트래픽)으로. 상세는 `SKILL.md` "모바일 환경(env) 확정".

3. **로딩 대기.**
   진입·로그인 후 스켈레톤이 사라질 때까지 대기 + **3~5초(최대 5초) 안전 대기** 후 조작 검증 시작.

4. **미반영 오탐 금지.**
   조작값이 화면에 안 보여도 "미반영" 단정 금지 — 사용자는 존재하는 원본을 조작 요청한 것이다.
   - 개인화 의존 섹션 → 사용자가 알려줌(그 때만 개인화 요인 고려).
   - 그 외 → **전체 화면을 끝까지 스크롤**하며 지연 마운트 섹션(랭킹/캐러셀/IntersectionObserver)을 노출시켜 가시 텍스트 + 속성(alt/title/aria)까지 훑어 찾는다.

5. **마크업 분리 자동 보정 (내가 감지·수정, 구조 되묻지 않음).**
   사용자 `find`는 화면에 보이는 텍스트(`131개`)인데 본문은 숫자·단위가 태그로 분리(`<span>131</span>개`)돼 매칭 안 될 수 있다. 미반영 확인 시 내가 직접:
   ① 실제 응답 바이트 확인(지면=브라우저 same-origin fetch, API=`curl|jq`) → ② 매칭되는 연속형(`131</span>개`→`522</span>개`) 또는 유일 최소형으로 규칙 재작성 → ③ `/__proxy/rules` upsert + `/__proxy/reload` 후 재검증.
   > 단, 값이 응답에 아예 없으면(개인화/지연/부재) 자동 보정 말고 **보류·확인**.

6. **결함 선언 규율.**
   검증환경 아티팩트를 제품 결함으로 오인 금지. ground truth 없이 결론·팀채널 게시 금지. 미검증은 보류·요청.

7. **앱 조작 — 텍스트 치환 전역 + 여러 엔드포인트 값은 내가 감지·실기기 대조.**
   `mitm_addon.py`의 텍스트 치환은 **전역**(모든 text/json 응답, 웹 엔진과 동일). JSON 필드만 경로 스코프. 같은 값(예 작가명)이 여러 API(`/v2/views/48`·`related-features` 등)에 걸쳐 있어도 한 번에 바뀐다. 조작값이 화면에 안 보여도 미반영 단정 금지 → ① 탐색 본문(`mobile_apis.json`)에서 값이 어느 엔드포인트에 있는지 감지(단, 탐색 본문은 **치환 전** 원본), ② 실기기를 스크롤/캐러셀로 탐색해 화면 노출 대조(uiautomator dump 텍스트가 스크린샷보다 정확), ③ 큰 지면은 캐시라 **앱 강제종료+재실행**으로 캐시 우회 재요청 후 검증. 상세는 `SKILL.md`. (실측: `/v2/views/48` 캐러셀 "원누리 #신파 완결!"→조작문구 화면 반영 확인)

8. **선택된 대상만 테스트 — 그 외 매체는 손대지 않는다.**
   신호의 `platform`/`mobileTarget`이 지정한 **바로 그 대상만** 검증한다. `platform=web`이면 **PC 웹 지면(URL)만** 본다 — 앱/모바일웹/API를 곁다리로 검증하거나 "혹시 몰라" 확인하지 않는다. 조작값이 안 보여도 다른 매체로 넘어가지 말고 선택 대상 안에서 [미반영 오탐 금지] 절차(전체 스크롤·속성 탐색)를 밟는다.
   - **PC 웹은 URL 지면만**: 텍스트 치환은 전역이라 SSR HTML에 이미 반영된다. `/v2/views/48` 같은 앱 API를 직접 호출·검증할 필요 없음(그 데이터는 서버가 SSR에 인라인). 렌더된 화면에서 조작값을 찾으면 끝.

9. **결과 스샷은 `test_proxy/results/`에 저장.**
   매 테스트 결과 스크린샷은 `test_proxy/results/` 폴더에 목적이 드러나는 이름(`<YYYYMMDD-HHMMSS>_<매체>_<env>_<지면>_<조작요약>.png`)으로 저장하고, 그 절대경로를 `/__proxy/result`의 `screenshotFile`로 게시한다. (Playwright 스샷 저장은 프로젝트 루트 하위만 허용 → `test_proxy/results/`로.)

> 위 규칙들의 실측 근거·구체 사례는 `MEMORY.md` 참조.

## 🎯 테스트 대상 3종 — 하나의 컨트롤패널에서 통합

패널 ①에서 대상 선택: **PC 웹 / 모바일 웹 / 모바일 앱**. 모바일이면 OS(AOS/iOS), 모바일웹이면 브라우저까지.
신호/state 매핑: `platform`(web/aos/ios) + `mobileTarget`(app/mweb) + `mobileBrowser`.

| 대상 | 조건 | 실행 | 사전조건 |
|---|---|---|---|
| **PC 웹** | `platform=web` | Playwright로 `localhost:3001` 접속 | 시스템 프록시 안 씀 → 맥 트래픽(슬랙 등) 영향 無 |
| **모바일 웹** | `aos/ios` + `mweb` | 휴대폰 브라우저 + mitmproxy | 피닝·디버그빌드 불필요. CA 신뢰만: iOS=무관 O / **AOS=Firefox 루팅 없이 O**, Chrome·삼성인터넷은 루팅 필요 |
| **모바일 앱** | `app` | appium + mitmproxy | **AOS는 디버그/QA 빌드 필요**(아래) |

> 어느 경우든 맥은 "리스너"일 뿐(프록시를 타는 건 브라우저=localhost / 휴대폰뿐). **맥 시스템 프록시는 안 건드림** → 테스트 중에도 맥 업무 정상.

## 📱 모바일 프록시 (mitmproxy) — 웹과 별개, 패널에서 통합 운영

- **엔진·CA는 맥(로컬)에**, 휴대폰엔 공개 CA만. mitmproxy는 `brew install`(설치됨). **Charles와 완전 별개**(CA 재사용 안 함).
- **기기 프록시 IP 공유**: 패널이 맥 en0(Wi-Fi) LAN IP 자동 감지 → `/__proxy/state`의 `mobileProxy`(`<ip>:8888`)로 노출. 와이파이 변경 시 패널에서 수동 입력(`mobileIpOverride`). **하드코딩 금지, 매번 state에서 읽기.** PC·기기 동일 Wi-Fi 필수. VPN(utun*)이어도 LAN 도달은 en0 기준이라 무관.
- **패널은 플랫폼별 구성이 갈린다**(web/aos/ios): 모드 배너 + `.only-web`/`.only-mobile` 섹션. 웹=로그인 자동화, 모바일=②연결(IP/CA/사전조건). 헷갈리지 않게 유지.
- **⚠️ AOS 사전조건**: 비루팅 Android에선 **user CA 신뢰 + 피닝 off 디버그/QA 빌드** 필요. 프로덕션만 있으면 복호화 불가 → 사용자에게 디버그 빌드 요청. *(현재 기기 상세는 `MEMORY.md`)*
- **CA 파일**: `~/.mitmproxy/mitmproxy-ca-cert.cer`(AOS)/`.pem`(iOS) = 같은 CA, 설치법만 다름. 개인키 `mitmproxy-ca.pem`/`.p12`는 기기 설치 금지.
